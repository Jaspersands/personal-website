Error correction, in your browser

A distance-5 rotated surface code with 25 data qubits and 24 stabilizers. Click a qubit to put an error on it. Stabilizers light up when they anticommute with that error. That pattern of lit stabilizers is all a real quantum computer gets to see, because measuring the error directly would collapse the state.

Decoding means working backwards from that pattern to a likely error. This is a small version of the Rust and WebAssembly simulator I built, which does the decoding properly with minimum-weight perfect matching.

Noise-Aware Adiabatic Simulation

IBM Heron hardware · transverse-field Ising model

Digitized adiabatic ground state preparation for the 1D transverse-field Ising model. I used the Heron processor's native fractional RZZ gates, which cut the logical-to-physical translation error roughly in half, plus a palindromic Trotter step for second-order accuracy. The energy gap closes near the critical point, so a linear sweep moves too quickly through the part that matters. Flattening the schedule around s꜀ slows it down there instead.

Entanglement & Matrix Product States

Many-body systems · theoretical study

A study of how bipartite entanglement structure controls MPS compression. I wrote a sequential SVD wavefunction decomposition in Python and measured Schmidt spectra, entanglement entropy at every cut, and fidelity under truncation. A product state needs bond dimension 1 and a Haar-random state needs exponentially many, so the useful cases fall somewhere between the two.

WASM QEC Simulator

Rust → WebAssembly · surface code decoding in the browser

A symplectic stabilizer simulator written in Rust and compiled to WebAssembly. It handles real-time error injection, syndrome visualization, and logical error benchmarking for rotated and XZZX surface codes. The decoders, including minimum-weight perfect matching, all run in the browser.

Threshold · exact MWPM 20k shots/pt

Phenomenological noise, T = d rounds, exact MWPM, measured on the simulator itself. The curves cross at about 3.3%: below it a bigger code wins, above it a bigger code just gives noise more places to land. Union-Find on the same sweep thresholds at 2.7%, and the code-capacity threshold is 14%.

LLM-Based Lossless Text Compression

Systems optimization

Throughput and memory limits for text compression using autoregressive LLMs with arithmetic coding. Average compression came out between 5× and 16×, with a best case of 39×, which beats both zstd and gzip. Static KV caching, CUDA graph capture, and segment-level batched inference are what made it fast enough to be usable.
